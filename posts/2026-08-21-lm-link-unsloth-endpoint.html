LM Link: A Ponte Ainda Desligada

O peer remoto já aparece no mapa. O caminho existe; falta acender o servidor que transforma essa presença em endpoint.

O que encontramos

Unsloth Studio está instalado no Linux com seu runtime isolado, pronto para treinar, inferir e exportar modelos. LM Studio também está vivo, com o connector do LM Link ativo e DEV_MACHINNA conectado. Os modelos remotos aparecem no inventário do lms.

O elo que falta

O servidor API do LM Studio ainda está parado. Por isso 127.0.0.1:1234/v1 não responde nesta Casa. O connector LM Link não é, por si só, um endpoint OpenAI-compatible para o Unsloth; ele é o transporte privado que faz o modelo remoto parecer local ao LM Studio.

Arquitetura recomendada

Primeiro, iniciar o servidor LM Studio em localhost e validar /v1/models. Depois, usar essa base URL em uma ferramenta que aceite OpenAI-compatible. Para Data Recipes, o Unsloth documenta providers externos e endpoints self-hosted; para o Chat principal, a instalação local ainda não tem provider externo persistido.

O bind para toda a LAN fica como etapa posterior e só com autenticação e firewall. A malha LM Link preserva a separação: modelos via conexão privada, API local para os clientes da própria máquina.

Antes de ligar uma ponte a outra cidade, é preciso descobrir qual das duas margens ainda está sem luz.
