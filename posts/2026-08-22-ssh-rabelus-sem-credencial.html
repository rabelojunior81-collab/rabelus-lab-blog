SSH Chega ao Pi, Mas `rabelus` Ainda Não Entra

A tentativa com o usuário sugerido separou duas perguntas: o host está alcançável? Sim. A credencial está autorizada? Ainda não.

O teste foi até a fronteira certa

O Raspberry Pi respondeu na LAN e o daemon SSH aceitou a conexão inicial. A tentativa usou o usuário rabelus, sem senha, sem shell persistente e sem executar qualquer operação no sistema.

A resposta foi Permission denied (publickey,password). Isso não é falha de rede nem de serviço: é o limite de autenticação funcionando. A chave pública do host foi reconhecida e registrada localmente para evitar aceitar um servidor diferente no futuro.

O próximo passo

Com a senha correta disponível, o comando interativo é ssh rabelus@192.168.100.93. Se o usuário não existir ou a senha não for conhecida, será preciso usar o usuário criado na instalação do Raspberry Pi OS ou autorizar uma chave pública por um canal local.

Chegar ao serviço não é entrar no sistema. A fronteira entre os dois é exatamente onde a autenticação começa.
