O Alvo de Cada CLI

A segunda rodada consultou os canais oficiais e trocou lacunas por versões-alvo verificáveis, sem executar nenhuma atualização.

Os alvos encontrados

Codex CLI sai de 0.152.0 para 0.153.4; Claude Code, de 2.1.252 para 2.1.261; OpenCode, de 1.18.25 para 1.18.29; Kimi Code, de 0.39.1 para 0.41.0; e AGY, de 1.1.22 para 1.1.27. As fontes foram, respectivamente, os registries/repositórios oficiais de OpenAI, Anthropic, OpenCode, Moonshot e Antigravity.

O Node instalado é 24.16.0. O alvo de manutenção é 24.20.0 LTS; 26.8.1 existe como Current, mas não é o alvo prudente para este conjunto de CLIs sem uma matriz de compatibilidade. TypeScript está em 7.0.2, que continua sendo a versão publicada no npm.

Os que já estão correntes

O changelog oficial confirma LM Studio 0.4.23 Build 1, equivalente ao bundle local 0.4.23+1. Ollama está em 0.33.3, igual ao release oficial e à fórmula Homebrew. A consulta nativa do macOS retornou sem novo software disponível. Nesses casos não há versão-alvo de atualização para promover.

Os dois feeds que continuam ausentes

Codex Desktop (26.901.41600) e Claude Desktop (1.46388.4) foram medidos pelo bundle. Seus canais públicos não expõem uma versão comparável nesta superfície; a confirmação precisa vir do updater interno de cada aplicativo. Isso fica registrado como teste pendente, não como “atualizado”.

O que a auditoria passa a permitir

Agora cada linha tem versão efetiva, fonte, alvo ou estado corrente e uma decisão. O próximo passo pode ser um lote R1 isolado, com snapshot, teste de compatibilidade e rollback. A existência do alvo não executa a mudança por si só. A evidência detalhada, incluindo os links oficiais e o horário da consulta, está no artefato upstream da auditoria.

Pacotes auxiliares também têm alvo

A mesma consulta confirmou Homebrew gh 2.96.0→2.100.0, pcre2 10.47_1→10.48, ripgrep 15.1.0→15.2.0, uv 0.11.29→0.12.10 e Tailscale 1.98.8→1.102.3. No npm global, @kilocode/cli vai de 7.4.11 para 7.5.14, Corepack de 0.35.0 para 0.36.0 e npm de 12.0.1 para 12.0.2. São candidatos verificáveis; o lote de execução continua separado por risco e rollback.
